# backend

FastAPI: API для жюри (раздел 10 ТЗ) и раздача сборки `frontend`. Обработка запускается через workflow `AnalyzeVideo` в Temporal; результат публикует CV worker (схема в `infra/README.md`).

## Запуск

```sh
uv sync
export ADMIN_KEY="$(openssl rand -hex 24)"
uv run backend      # http://127.0.0.1:8000, docs: /docs
uv run pytest
```

Нужны `ffmpeg` и `ffprobe` в PATH.

| Переменная | По умолчанию | Что |
|---|---|---|
| `ADMIN_KEY` | обязателен, иначе запуск прерывается | общий токен для интерфейса, `X-API-Key` и Bearer |
| `SESSION_COOKIE_SECURE` | false (локальный HTTP) | true для публичного HTTPS |
| `MAX_UPLOAD_MB` | 200 | лимит размера видео |
| `FRONTEND_DIST` | `../frontend/dist` | если каталог есть, отдаётся на `/` |
| `HOST`, `PORT` | 127.0.0.1, 8000 | |

Compose: `../infra/init-access.py` переносит существующий ключ из `.env` в игнорируемый Git локальный override. Для HTTPS используйте `--https`. В интерфейсе одно поле токена; доступ сохраняется в подписанной cookie на 12 часов. `/docs` открывается после входа. Токены ботов — Coming soon. Подробнее: [контракт API](docs/API.md).

## API

```sh
curl -X POST http://127.0.0.1:8000/api/v1/analyze -H "X-API-Key: $ADMIN_KEY" -F "file=@video.mov"
# {"job_id":"3f2a9c1e0b7d"}
curl http://127.0.0.1:8000/api/v1/jobs/3f2a9c1e0b7d -H "X-API-Key: $ADMIN_KEY"
```

- `status`: `processing` → `done` | `failed`. При `done` есть `verdict` (`violation` / `no_violation`) и `violations`.
- В `violations[]` поля строго по ТЗ: `type`, `timecode_sec`, `description`, `evidence_frames` (1–3 JPEG в base64 без префикса `data:`).
- Сверх ТЗ: `rule` {`document`, `clause`, `url`} для интерфейса и `error` при `failed`. В схеме ТЗ места для норматива нет, поэтому ссылка на него дублируется в конце `description`: жюри проверяет автоматически по этой схеме.
- Эти два метода требуют именно `X-API-Key`: Bearer и браузерная cookie используются только остальными методами интерфейса. Не `.mov` → 415, без заголовка или с неверным ключом → 401, неизвестный `job_id` → 404.
- До сохранения и запуска задачи проверяется декодирование первого видеопотока: должен получиться хотя бы один кадр. MOV без декодируемых кадров (например, с неизвестным кодеком) отклоняется с 422, а не получает `no_violation`. Проверка ограничена 15 секундами и оставшимся общим бюджетом; её тайм-аут возвращает 504.
- Декодируемый MOV с кодеком, который нельзя перепаковать в MP4, принимается для анализа. Копия для плеера необязательна; исходное видео сохраняется в S3.
- Общий бюджет задачи — 270 секунд от начала приёма POST, включая загрузку, подготовку и очередь; оставшиеся 30 секунд до лимита жюри отведены на получение ответа. Просроченный результат не публикуется как `done`.
- При недоступном Temporal уже созданная задача возвращается с `job_id` и статусом `failed` при опросе. Ошибка хранилища/БД при загрузке → 503; превышение срока приёма/подготовки → 504. Один запрос чтения результата ограничен 20 секундами: если БД или S3 не отвечают вовремя, GET возвращает 503.
- Результат с отсутствующими, повреждёнными или не-JPEG кадрами, неверными таймкодами или противоречащим событиям вердиктом получает `failed`. Отсутствие доказательств не означает `no_violation`.
- Разные типы событий сохраняются отдельными нарушениями, в том числе без `title` (тип берётся из `event`). Ручные отметки интерфейса не меняют опубликованный результат модели для жюри.

Модели ответа — `src/backend/schema.py`; frontend держит такие же типы.

## Проверка

`uv run pytest` запускает тесты API, доступа, сроков и публикации результатов. Требуются `ffmpeg` и `ffprobe` в PATH. Проверки используют SQLite и S3 в памяти; запуск Temporal подменён. Отдельно проверяются настоящие JPEG, MOV с QuickTime Animation и чтение `botocore.StreamingBody`.

Для приёмки развёртывания нужно запустить backend вместе с CV-worker, Temporal, S3 и БД; передать жюри публичный адрес и действующий ключ; проверить на целевом оборудовании видео с несколькими нарушениями и без нарушений. Прохождение тестов backend не подтверждает качество модели и скорость полного стека.
